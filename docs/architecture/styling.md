# Стили: как писать компонент

**Tailwind-утилиты по умолчанию; для сложного — SCSS-модуль рядом с компонентом.**

Документ — правило для любой новой или изменённой вёрстки. Почему выбран Tailwind,
какие были альтернативы и как менялся размер CSS — в архиве OpenSpec-изменения
`migrate-styles-to-tailwind`; здесь только то, что нужно, чтобы писать правильно.

---

## Утилиты или модуль

Решает каждая группа деклараций отдельно. **В модуль** идёт то, что утилитами не
сказать или что в них нечитаемо:

1. **Псевдоэлемент** — `::before`, `::after`: линия таймлайна, маркеры списка.
2. **Состояние предка или соседа** — «наведи на ссылку, иконка станет ярче». Так же —
   несколько состояний одного элемента, которые переопределяют друг друга
   (`:hover` и `[aria-current]`). Одно собственное состояние — `hover:`, `focus:`,
   `data-filled:` — остаётся утилитой.
3. **Шаблон сетки** — `grid-template-columns`, в том числе `repeat()` и `minmax()`.
4. **Медиазапрос компонента**, который утилита-брейкпоинт не выразит: включительный
   `max-width: 62rem`, шаблон сетки или несколько свойств под одним условием. Одно-два
   простых свойства под брейкпоинтом — это утилиты: `md:gap-2xl`, `md:items-start`.
5. **Полупрозрачный слой** — свечение, градиент подложки, а также плавающий
   `clamp()` для одного места (`padding-block: clamp(…)` в hero).
6. **Значение по умолчанию, которое родитель вправе переопределить**: утилита
   родителя перебивает модуль, поэтому и сам умолчательный `gap` у `AppLink` лежит в модуле.
7. **Составное значение** с `calc()` и токенами: в модуле оно читается как обычное
   свойство, а произвольной утилитой вышло бы длинной строкой в `class`.

**Всё остальное — утилиты**: `flex`/`grid`, выравнивание, отступы, кегль, вес и цвет
(в том числе `hover:`), границы, радиусы, тени, размеры.

**Пример без модуля** — [`ThemeToggle.vue`](../../app/components/ThemeToggle.vue):
одна кнопка, у неё только утилиты; своё состояние — `hover:`.

```vue
<button
  type="button"
  class="inline-flex size-11 cursor-pointer items-center justify-center rounded-pill border border-border-interactive bg-transparent text-muted transition-colors hover:border-accent hover:bg-accent-veil hover:text-accent"
  @click="toggle"
>
```

**Пример с модулем** — [`LocaleSwitcher.vue`](../../app/components/LocaleSwitcher.vue):
устройство ссылки — утилиты, цвет с его состояниями (наведение, текущий язык) — модуль.

```vue
<NuxtLink
  :class="[$style.link, 'inline-flex min-h-9 min-w-10 items-center justify-center rounded-pill px-2 text-sm font-semibold no-underline transition-colors']"
  :aria-current="item.code === locale ? 'true' : undefined"
>

<style module lang="scss" src="./LocaleSwitcher.module.scss"></style>
```

```scss
// LocaleSwitcher.module.scss
@layer components {
  .link {
    color: var(--text-muted);

    &:hover { color: var(--text); background: var(--surface-2); }
    &[aria-current='true'] { background: var(--accent); color: var(--accent-contrast); }
  }
}
```

Как подключить модуль:

- рядом с компонентом лежит `<Component>.module.scss`, весь код внутри `@layer components { … }`;
- в компоненте — пустой тег `<style module lang="scss" src="./<Component>.module.scss"></style>`,
  в нём **нет** правил (так Nuxt кладёт CSS в пререндеренную страницу);
- в шаблоне — `:class="$style.link"`, вместе с утилитами — `:class="[$style.link, 'flex']"`;
- `:global(…)` нужен только там, где правило должно выйти за пределы модуля, например
  к атрибуту на `<html>`: `:global(:root[data-theme='dark']) &`. Сейчас ни один компонент
  им не пользуется: тема идёт через `light:` и `dark:`.

Как сейчас поделены компоненты — чтобы правило можно было приложить к живому коду:

| Компонент | В модуле | Почему |
| --- | --- | --- |
| `AppIcon`, `ThemeToggle`, `AppFooter`, `layouts/default` | — | только утилиты |
| `AppLink` | отступ по умолчанию; иконка и её реакция на наведение | п. 6 и п. 2 |
| `SkipLink` | `transform` за краем экрана и его снятие по фокусу | п. 7 |
| `LocaleSwitcher` | цвет, наведение, `[aria-current]` | п. 2 |
| `AppHeader` | сворачивание `max-width: 62rem`, `data-open`, состояния ссылки, кнопка-бургер | п. 4 и п. 2 |
| `HeroSection` | свечение, отступ `clamp()`, шаблон сетки статистики | п. 5 и п. 3 |
| `AboutSection`, `SkillsSection` | шаблон сетки | п. 3 |
| `ExperienceSection` | линия и маркеры (`::before`), колонки раннего опыта от 44rem | п. 1 и п. 4 |
| `EducationSection` | колонки страницы от 56rem, шаблон строки языка | п. 3 и п. 4 |
| `ProjectsSection` | шаблон сетки, градиент выделенной карточки от 56rem | п. 3 и п. 5 |
| `ContactSection` | отступ `clamp()` и градиент карточки, шаблон сетки соцсетей | п. 5 и п. 3 |

## Слои и приоритет: утилита сильнее модуля

Порядок слоёв: `properties, theme, base, components, utilities`.

- `base` — [`reset.css`](../../app/assets/css/reset.css) (сброс проекта; Preflight от Tailwind не подключён), типографика, ссылки, фокус;
- `components` — все модули;
- `utilities` — утилиты Tailwind и примитивы проекта.

Утилита на элементе всегда перебивает правило модуля, а не наоборот, в каком бы порядке
файлы ни попали на страницу. Отсюда три следствия:

1. **Если модуль переопределяет свойство в каком-то состоянии или под медиазапросом,
   базовое значение этого свойства лежит в том же модуле.** Иначе утилита с базовым
   значением перебьёт состояние (так устроены `LocaleSwitcher` и `AppHeader`).
2. **Модуль не может переопределить то, что задаёт утилита или примитив на том же
   элементе** (`card`, `btn`). Нужен вариант-утилита (`md:border-border-strong`) или другое
   свойство: `card` задаёт `background-color`, поэтому градиент карточки — `background-image` в модуле.
3. **Примитив не задаёт то, что компонент-обёртка должна уметь переопределить.** Поэтому у
   `btn` нет `gap`: кнопке с иконкой добавляют `gap-2`, а у ссылки-кнопки промежуток
   приходит из `AppLink`.

Порядок слоёв объявляется один раз, первой строкой `<head>` — в `nuxt.config.ts`
(`app.head.style`, тот же список, что объявляет Tailwind). Слои упорядочены по первому
упоминанию в документе, а Nuxt вставляет стили компонентов раньше подключаемого стиля
Tailwind; без этой строки `components` оказался бы ниже `base`.

## Имена

- Общие примитивы — плоские имена: `btn`, `card`, `tag`, `section-head`. Это `@utility` в
  [`main.css`](../../app/assets/css/main.css), они принимают варианты (`md:card`, `hover:btn-primary`).
- Классы в модуле — короткие, camelCase, без префикса компонента: `glow`, `stats`, `earlyItem`.
  Модуль изолирован (`generateScopedName`, хеш от пути файла и имени), поэтому два компонента
  могут назвать класс одинаково, например `link`.
- **BEM (`block__element`, `block--modifier`) нигде не используется.**
- Состояние — атрибутом, а не классом: `aria-current`, `aria-expanded`, `data-open`, `data-filled`.
- Видимость по теме — вариантами `light:` и `dark:`, а не отдельными классами.

## Значения

Значения берутся из токенов в [`main.css`](../../app/assets/css/main.css); палитра
Tailwind по умолчанию очищена, поэтому `text-red-500` не даёт ни одного правила.

| Что | Как писать |
| --- | --- |
| Цвет | `text-fg`, `text-muted`, `text-subtle`, `text-accent`, `bg-surface`, `bg-surface-2`, `border-border`, `border-border-strong`, `border-border-interactive`, `bg-accent-veil` … |
| Кегль | `text-sm` … `text-4xl` (плавная шкала `--step--1` … `--step-5`) |
| Вес | `font-normal` 400, `font-medium` 500, `font-emphasis` 550, `font-semibold` 600, `font-strong` 650, `font-bold` 700 |
| Радиус | `rounded-s`, `rounded-m`, `rounded-l`, `rounded-pill`; для круга — `rounded-full` |
| Тень | `shadow-card` |
| Отступы | шаг Tailwind = 4px (`p-1` = 4px, `min-h-12` = 48px) и именованные шаги ритма: `gap-xl`, `py-3xl` |
| Переход | `transition-colors` (180 мс, кривая проекта) |
| Брейкпоинты | `sm:` = 44rem, `md:` = 56rem, оба через `min-width` |
| Контейнер, ширина строки | `container`, `max-w-(--measure)` |

Вес 550 и 650 не входят в шкалу Tailwind, поэтому заведены отдельно: округление до 500/600
заметно меняло бы переменный шрифт. Необработанное числовое значение веса пишется
только в определении токена.

Общие примитивы: `container`, `section`, `section-head`, `eyebrow`, `card`, `btn`,
`btn-primary`, `btn-ghost`, `tag`, `tag-list`, `prose`. Границы для режима высокой
контрастности (`forced-colors`) вложены в сами примитивы.

Варианты по теме: `light:` — явный `data-theme='light'` или, пока выбора нет, системная
светлая тема; `dark:` — зеркально. Это чистый CSS, поэтому разметка сервера и клиента
совпадает и при гидратации нечему расходиться. `hover:` — обычный `:hover` (у Tailwind по
умолчанию он включается только на устройствах с настоящим наведением, здесь — везде, как раньше).

**Произвольные значения** допустимы для величин, привязанных к тексту, и безразмерных:
`leading-[1.55]`, `tracking-[0.08em]`, `gap-[0.4ch]`, `max-w-[44ch]`. Произвольные отступы
и размеры в `rem`/`px` — нет: возьмите шаг сетки или именованный шаг.

## Сетка 4px

Каждый padding, margin, gap, inset и размер (в том числе `min-`/`max-`) в `rem`/`px` кратен
4px (0.25rem) или является именованным шагом. Исключения: линии в 1–2px (границы, разделители),
плавающие значения `clamp()` и величины в `ch`, `em`, `%`. Округляют к ближайшему
кратному 4px, а ровно посередине — вверх, чтобы цели нажатия не уменьшались: интерактивная
цель, бывшая не меньше 44×44, остаётся не меньше, любая другая не падает ниже 24×24.

## Чего нельзя

- Правила в теге `<style>` компонента: в нём разрешён только `src` на модуль, тело пустое.
- BEM-имена и классы состояния (`is-open`, `is-filled`).
- Числовой `font-weight` вне определения токена.
- Отступы и размеры вне сетки, включая произвольные (`gap-[0.35rem]`).
- Цвета, кегли и радиусы вне токенов.
- Селекторы по классам в тестах — там ищут по роли, имени и `data-testid`
  (см. README, «Как находить элементы в тестах»).
- Правила модуля вне `@layer components`.

## Как это проверяется

Команды запускаются из корня репозитория. Поиски из блока ниже ничего не выводят, если
всё в порядке; остальные завершаются успешно.

| Правило | Проверка |
| --- | --- |
| Сетка 4px, включая произвольные значения утилит | `node scripts/check-grid.mjs` |
| Классы в тестах | входит в `pnpm test:a11y`: `scripts/check-test-selectors.mjs` идёт до Playwright |
| Доступность и поведение после правки стилей | `pnpm test:a11y` |
| Токены тем читаются скриптом, контраст | `pnpm check:contrast` |
| Размер CSS не вырос | `pnpm measure:css` (сборка и замер; `pnpm measure:css --compare до.json после.json` — сравнение) |
| Цвета вне палитры | конфигурация: в очищенной шкале для них нет ни одного правила |
| Тело у `<style>`, BEM, классы состояния, числовой вес, произвольные отступы | ревью, с поисками ниже |
| Разбиение на утилиты и модуль | ревью: правило из раздела «Утилиты или модуль» |
| Модуль обёрнут в `@layer components` | ревью |

```bash
# тело у <style> в .vue (в теге разрешён только src на модуль)
grep -rn '<style' app --include='*.vue' | grep -v '></style>'

# BEM в шаблонах и в стилях
grep -rnE '[a-z0-9](__|--)[a-z]' app --include='*.vue'
grep -rnE '(^|[^-[:alnum:]_(])\.[[:alnum:]]+(__|--)[[:alpha:]]' app --include='*.scss' --include='*.css'

# BEM в готовом HTML (после pnpm generate)
grep -ohE 'class="[^"]*"' .output/public/index.html .output/public/en/index.html | grep -E '[a-z0-9](__|--)[a-z]'

# классы состояния
grep -rnE "(^|[[:space:]'\".])is-[a-z]" app --include='*.vue' --include='*.scss' --include='*.css'

# числовой вес шрифта
grep -rnE 'font-weight:[[:space:]]*[0-9]|font-\[[0-9]' app

# произвольные отступы и размеры в rem/px
grep -rnE '(^|[^[:alnum:]-])-?(p[xytblrse]?|m[xytblrse]?|gap(-[xy])?|inset(-[xy])?|top|right|bottom|left|start|end|space-[xy]|size|(min-|max-)?[wh])-\[[^]]*(rem|px)' app --include='*.vue'
```
