# Портфолио — Бексултан Карабаев

Одностраничный сайт-портфолио на **Nuxt 4** (Vue 3), двуязычный (RU / EN),
со статической генерацией, разметкой Schema.org и проверенной доступностью.

---

## Быстрый старт

```bash
pnpm install
pnpm dev          # http://localhost:3000
```

| Команда | Что делает |
| --- | --- |
| `pnpm dev` | Дев-сервер с горячей перезагрузкой |
| `pnpm generate` | Статическая сборка в `.output/public` |
| `pnpm preview` | Посмотреть собранный сайт локально |
| `pnpm typecheck` | Проверка типов (`vue-tsc`) |
| `pnpm check:contrast` | Проверка палитры на соответствие WCAG 2.2 AA |

---

## ⚠️ Перед публикацией: задайте адрес сайта

Пока адрес не задан, используется заглушка `https://example.com` — и canonical,
hreflang, sitemap и Open Graph будут указывать в никуда.

```bash
NUXT_PUBLIC_SITE_URL="https://ваш-домен.ru" pnpm generate
```

На хостинге пропишите ту же переменную окружения (`NUXT_PUBLIC_SITE_URL`)
в настройках проекта.

## Где править содержимое

Весь текст о вас лежит в одном файле — **[`app/data/profile.ts`](app/data/profile.ts)**.
Вёрстка, структурированные данные и метатеги собираются из него автоматически.

```ts
export const profile: Profile = {
  name: { ru: 'Бексултан Карабаев', en: 'Bexultan Karabayev' },
  // ...
}
```

Каждая строка задана сразу на двух языках: `{ ru: '…', en: '…' }`.
Названия, которые не переводятся (`'SplitCheck Bot'`, `'Vue 3'`), пишутся
обычной строкой.

Что где лежит:

| Файл | Содержимое |
| --- | --- |
| `app/data/profile.ts` | Имя, опыт, проекты, навыки, образование, контакты |
| ↳ `experience` | Основной опыт: компания → должности → результаты |
| ↳ `earlyCareer` | Блок «До фронтенда»: одна строка на место, без списка задач |
| `shared/types/profile.ts` | Типы контента — подсказывают структуру при правке |
| `i18n/locales/ru.json`, `en.json` | Подписи интерфейса: пункты меню, кнопки, заголовки разделов |
| `app/assets/css/main.css` | Палитра, типографика, базовые стили |
| `public/og-ru.png`, `og-en.png` | Картинки для превью в соцсетях (1200×630) |

Номер из резюме на сайте **не публикуется** — открытый номер быстро собирают
спам-боты. Если он нужен, в `profile.socials` есть закомментированный пример.

## Языки

Работает на `@nuxtjs/i18n` со стратегией `prefix_except_default`:

- `/` — русский (язык по умолчанию)
- `/en` — английский

При первом заходе на `/` посетителя переносит на его язык по заголовку браузера,
выбор запоминается в cookie. Переключатель языка — настоящие ссылки, поэтому
работает без JavaScript и индексируется поисковиками.

Добавить язык: впишите локаль в `nuxt.config.ts` → `i18n.locales`, создайте
`i18n/locales/<код>.json` и добавьте ключ в каждый объект `{ ru, en }` в
`profile.ts` (TypeScript подскажет все места, где не хватает перевода).

## Доступность

Проверено `axe-core` 4.10 на собранном сайте — **0 нарушений** на обеих
страницах (`/` и `/en`) в светлой и тёмной теме, по правилам
WCAG 2.0/2.1/2.2 уровней A и AA плюс best-practice.

Что сделано:

- **Структура.** Ориентиры `header` / `nav` / `main` / `footer`, заголовки
  строго по уровням h1 → h2 → h3 → h4 без пропусков, у каждого раздела свой
  `aria-labelledby`.
- **Клавиатура.** Ссылка «Перейти к содержимому» первым табом; фокус виден
  всегда (`:focus-visible`, контрастная рамка 3px) и нигде не убирается без
  замены; переход по якорю переносит фокус в раздел, а не только прокручивает.
- **Меню на мобильных.** Кнопка с `aria-expanded` / `aria-controls`, Escape
  закрывает и возвращает фокус на кнопку. Закрытое меню скрыто через
  `display: none` — значит, его нет ни в табуляции, ни у скринридера.
- **Контраст.** Все сочетания текста и фона проходят AA, включая фоны с
  полупрозрачными градиентами, которые автоматические проверки посчитать не
  могут. Границы интерактивных элементов — не ниже 3:1 (WCAG 1.4.11).
  Пересчитать после правки палитры: `pnpm check:contrast`.
- **Переключатель темы.** Состояние переключается только на CSS, поэтому
  скринридер всегда читает ровно одну подпись — ту, что соответствует действию.
- **Языки.** `lang` на `<html>` меняется вместе с локалью; название языка в
  переключателе размечено своим `lang`, чтобы синтезатор речи произнёс его верно.
- **Внешние ссылки.** `rel="noopener noreferrer"`, видимая иконка и текст
  «откроется в новой вкладке» для скринридера.
- **Настройки пользователя.** `prefers-reduced-motion` отключает все анимации
  и плавную прокрутку; `prefers-color-scheme` задаёт тему по умолчанию; есть
  запасные стили для режима высокой контрастности Windows (`forced-colors`).
- **Цели нажатия** не меньше 44×44 CSS-пикселей.

### Как перепроверить

```bash
pnpm check:contrast          # палитра
pnpm generate && pnpm preview
```

`pnpm check:contrast` остаётся главной проверкой контраста на
полупрозрачных слоях. axe не умеет складывать такие слои: свечение hero
(`--glow`), полупрозрачную шапку (`--bg-veil` + `backdrop-filter`) и
подложки на `--accent-veil` он помечает как `incomplete` — «не смог
посчитать», а не «нарушение». `check:contrast` берёт токены из `main.css`,
складывает слои сам и считает итоговые сочетания (`hero + свечение`,
`карточка + акцент`). Поэтому после любой правки палитры смотреть надо на
него, а не на результат axe.

Затем в DevTools на открытой странице:

```js
const s = document.createElement('script')
s.src = 'https://cdnjs.cloudflare.com/ajax/libs/axe-core/4.10.2/axe.min.js'
document.head.appendChild(s)
// после загрузки:
await axe.run(document, { runOnly: { type: 'tag', values: ['wcag2a', 'wcag2aa', 'wcag21aa', 'wcag22aa'] } })
```

## SEO

- **Статическая генерация.** Весь контент лежит в HTML — поисковику не нужно
  исполнять JavaScript, чтобы его увидеть.
- **Метатеги** на каждый язык: `title`, `description`, Open Graph (`og:type=profile`
  с именем и фамилией), Twitter Card `summary_large_image`.
- **Картинки для соцсетей** 1200×630 на каждый язык, с `og:image:alt`.
- **`canonical`** на каждой странице и **`hreflang`** для обоих языков плюс
  `x-default`.
- **Schema.org** — граф `WebSite` + `ProfilePage` + `Person`: должность,
  навыки, языки, образование, `sameAs` на GitHub и LinkedIn. Именно по этой
  разметке поисковики собирают карточку человека.
- **`sitemap.xml`** с hreflang-альтернативами и **`robots.txt`** — генерируются
  модулями. Ничего не закрыто от индексации: Googlebot должен видеть CSS и JS,
  иначе он отрендерит страницу неправильно.
- **Шрифты** скачиваются на сборке и раздаются со своего домена — без запроса к
  Google Fonts, без сдвига макета при загрузке.

Проверить разметку после публикации:
[Rich Results Test](https://search.google.com/test/rich-results) ·
[Schema Markup Validator](https://validator.schema.org/)

## Публикация

После `pnpm generate` в `.output/public` лежит обычная статика — подойдёт
любой хостинг:

```bash
pnpm dlx vercel deploy --prebuilt     # Vercel
pnpm dlx netlify deploy --prod --dir=.output/public
```

Для GitHub Pages, S3 или nginx просто выложите содержимое `.output/public`.
Не забудьте задать `NUXT_PUBLIC_SITE_URL`.
